# Бриф проекта: небольшая социальная сеть

## Идея

Закрытая небольшая соцсеть примерно для 10 пользователей. Пользователи публикуют картинки, ставят эмоции и оставляют комментарии.

## Подтверждённые требования

- API планируется написать на FastAPI.
- Главная учебная цель — backend-разработка, работа с базой данных и Docker.
- Frontend не является учебным приоритетом и может быть создан с помощью vibe coding.
- Пользователи самостоятельно регистрируют аккаунт, указывая почту, отображаемый ник и пароль.
- Первую учётную запись владельца с правами администратора создают при первоначальной настройке проекта.
- Пользователи смогут менять отображаемый ник и загружать аватарку.
- В ленте будут публикации с картинками, эмоциями и комментариями.
- Разработчик проекта пишет код самостоятельно; помощник выступает куратором: помогает планировать этапы, объясняет решения и разбирает ошибки, но не пишет код за разработчика.

## Рабочий вариант стека

- Backend: FastAPI, как отдельный REST API.
- База данных: PostgreSQL.
- Доступ к данным: SQLAlchemy 2; миграции схемы через Alembic.
- Локальная среда: Docker Compose для запуска API и PostgreSQL.
- Тесты backend: pytest.
- Frontend: отдельный тонкий клиент, например React + TypeScript; его можно создавать с помощью vibe coding. Главный фокус обучения остаётся на backend.
- Изображения: локально — постоянный Docker volume; при публикации — постоянное файловое или объектное хранилище.

Это рабочее предложение, которое можно уточнить до начала реализации.

## Тестирование backend

- Backend-функции покрываются тестами по мере реализации, а не только перед релизом.
- Unit-тестами проверяются отдельные правила и вычисления, которым не нужна база данных.
- Интеграционными тестами проверяются работа с PostgreSQL, ORM-модели, ограничения базы и API; для них используется локальная или отдельная тестовая база, но не production.
- Для аккаунтов и профилей проверяются регистрация, уникальность почты, безопасное хранение пароля и изменение собственного профиля.
- Для публикаций, комментариев и реакций тестируются правила доступа и поведения, зафиксированные в требованиях проекта.
- Тесты запускаются через pytest; существующий тест подключения проверяет доступность PostgreSQL, но не заменяет тесты функций приложения.

## Технические заметки

- Разделять аккаунт и профиль: аккаунт хранит почту, хэш пароля, статус и роль; профиль хранит изменяемый отображаемый ник и путь или ссылку на аватарку. Один профиль связан с одним аккаунтом.
- Почта аккаунта уникальна без учёта регистра.
- Пароли хранить только в виде хэша, не в открытом виде. Для защищённых маршрутов определять текущего пользователя по сессии или токену, а не доверять переданному клиентом `user_id`.
- В базе хранить ссылку или путь к изображению, а не его содержимое. Проверять формат и ограничивать размер загружаемых файлов.
- Docker volume сохраняет локальные данные контейнера при пересоздании контейнера, но не заменяет резервные копии.
- Простое правило для реакций: одна активная эмоция от пользователя на одну публикацию; повторный выбор меняет её.
- Бесплатный хостинг может подойти для пробного запуска, но у него могут быть ограничения на сон приложения, объём данных и трафик. Нужны HTTPS, секреты через настройки окружения и резервные копии.

## Возможный порядок разработки

1. Создание первой учётной записи владельца при настройке; самостоятельная регистрация пользователей по почте, нику и паролю; вход и изменение отображаемого ника.
2. Создание публикации с картинкой и получение ленты.
3. Комментарии.
4. Реакции.
5. Развёртывание с постоянной базой данных и хранилищем изображений.

## Открытые решения

- Нужны ли подтверждение почты и ограничение регистрации; как пользователи будут восстанавливать пароль.
- Где будут размещаться API, база данных и изображения.
- Какие виды эмоций будут доступны.
- Нужны ли подписи к картинкам, редактирование и удаление публикаций.
